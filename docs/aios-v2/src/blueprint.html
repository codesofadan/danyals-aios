02 · Principles
Non-negotiable

Ten rules. Each one is
a defect v1 shipped.

These are not style preferences. A change that violates one is rejected in review regardless of whether its tests pass.

P1

Never invent data

An unconfigured provider returns a degraded result — never a plausible number. Enforced by a CI gate over every writing path.

P2

Three states, never two

Measured, absent and unmeasured are different facts. Every ratio divides by measured only.

P3

Degrade, never crash

Every external seam returns a typed result with a machine-branchable reason. No caller parses a message string.

P4

Terminal states are honest

A publish with no credentials is blocked, not done. Success requires the effect to be confirmed.

P5

Money is gated first

The estimate gates before the call; the actual is committed after. A blocked call never reaches the provider.

P6

The database enforces tenancy

Forced row-level security on every client table. Application code is the second line of defence, never the first.

P7

Jobs are idempotent

Durable, resumable, retried with bounds, dead-lettered with context. Re-running never double-spends or double-publishes.

P8

Provenance on every value

Measured, derived, declared, inferred or defaulted — with source and timestamp. No provenance, no display.

P9

Secrets are sealed

Envelope-encrypted, per client, audited on read. Never in a log, a response, a job payload or a trace.

P10

Tests prove behaviour

Every test must fail when its defect is re-injected. One that passes against a broken implementation is deleted, not kept.

v1 had roughly 4,900 tests and still shipped a form-filler that reported success while filling a honeypot.
The test could not fail: the environment made its branch unreachable. Test count is not the metric — non-vacuity is.

A job's state and its side-effect rows commit in the same transaction. That single property removes v1's whole class of phantom successes.

AIOS v2 · Build Blueprint05
04 · The job engine
The foundation

The piece v1 did not have

Almost every v1 reliability failure traces to work that could run twice, could not resume, and could not honestly say what it had done.

Terminal states — each one distinct, each one true

succeeded

The effect was confirmed — not attempted.

partial

Some children completed, some did not.

failed

Retryable attempts exhausted.

blocked

A precondition is missing — no credentials, no capability, cost refused.

timed_out

Exceeded its limit. Not the same as failed.

dead

Dead-lettered with full context, requeueable.

Eight guarantees

At-least-onceLease with heartbeat. A worker that dies has its lease expire and the job is re-picked.
Effectively-once effectsIdempotency key → side-effect ledger. Recorded before attempt, checked before retry.
Atomic state + effectState and its outbox event commit together. No window where a page is published and the ledger does not know.
Bounded retryBackoff with jitter; retryable and terminal failures distinguished by class, not by string.
Dead letterFull error chain, last provider response, one-click requeue.
Honest terminal stateSuccess requires confirmation of the effect.
Caps and fairnessPer-client concurrency and per-provider rate limits checked at lease time. One client's 50-page run cannot starve the rest.
ResumabilityParent/child ledger plus checkpointed AI graph state. A restart resumes at the first incomplete child.

Schedules ship disabled and are enabled one module at a time, only after that job kind survives the chaos suite. This is the deliberate inverse of v1, where the scheduler was off because the jobs were unsafe — and nobody could tell which.

Provenance decides which source wins

declaredA CSS custom property the author wrote. It carries a name, which no clustering can recover. Highest rank.
derivedClustered computed styles from the rendered page. Covers every role the declarations miss.
inferredExtrapolated for a section the source site never had. Labelled as such to the reviewer.

The publish requirement — and what fails it

✓ Required

  • A real Elementor element tree: container → container → widget
  • Every heading, paragraph, image and button an addressable widget
  • Colours and fonts referenced through Elementor global tokens, so a client restyle propagates
  • Written via the companion plugin, which regenerates Elementor's CSS cache

✗ Explicit failure

  • The whole page inside one HTML widget
  • Hard-coded hex values the client cannot restyle
  • A raw REST meta write — the page renders unstyled
  • Reporting done when no credentials existed

Acceptance is physical: open the published page in Elementor, select any element, edit it, save. That is the test. v1 never built this, and it is the difference between a product and a demo.

Mappings cached on structure

The cache key is a fingerprint of form shape — field order, types, label shapes. Never the URL, never CSS selectors: directories rotate class names per load and reuse one form across many URLs.

A cache hit returns a plan in under 400 ms with no model spend. The fiftieth client on a directory costs almost nothing.

Honeypots: zero, not "low"

v1's filler put the client's website into a honeypot named url and truthfully reported success, while the directory silently discarded every submission.

Now: hidden, off-screen and decoy fields are classified ignore; the model reads "leave this empty" beside an input, which no heuristic can. Touching one is a hard failure. The eval bar is 0%.

09 · Measurement
M07 · M09

The numbers a client keeps

This is where every integrity rule either pays off or fails publicly. Tracking output goes straight into client reports.

Three states, enforced by the database

ranked
Measured, and found at position N.
absent
Measured, and not present in the result set.
error
Never measured — rate limit, timeout, provider failure.

Collapsing absent and error renders a rate-limited afternoon as a client's service area collapsing — permanently, in an append-only table, in a report they keep. A CHECK constraint makes the blur impossible, and every ratio divides by measured points only.

Three sources, never mixed

DataForSEOOrganic rank position, SERP features, competitors.Never local pack or grid
serper.devLocal pack presence and geo-grid points, queried by coordinate.Never organic history
Search ConsoleFirst-party impressions, clicks, CTR, average position.An average is not a rank

The v1 grid was fiction

It sent location="lat,lng" into a parameter that expects a place name, returning an unlocalised SERP for every point — a perfectly smooth, entirely fictional heat map. The fix is not cosmetic: the old data is worthless.

Publishing is not the deliverable

An indexed page is. Submissions that would exceed quota are queued, never dropped, and indexation is verified rather than assumed. unknown is a real state and is shown as one.

Caching is the cost model

A 50-page run reuses the same client context 50 times. Stable prefix first, volatile content after the last breakpoint, and cache-hit rate charted per module so a silent invalidator gets caught.

The judge is never the generator

Evaluation uses a different prompt and a different tier configuration from the thing it grades. Six eval suites gate CI against fixed fixtures.

The agent cannot submit

The citation graph has no submit tool. Scraped content enters prompts as clearly-delimited data, and nodes that read it have no tools at all.

Definition of done

  • Behaviour matches the requirement, including its failure modes
  • Every failure mode has an honest terminal state
  • Migration is forward-only and applies from zero
  • New tenant tables have forced RLS and a policy
  • Every paid call passes the cost gate
  • Every test fails when its defect is re-injected
  • Types clean, no unjustified escapes
  • OpenAPI and the typed clients regenerated
  • Traces, logs and metrics emitted
  • Verified in the running system, with evidence

12 · Roadmap
Exit criteria, not dates

Ten milestones.
The order is load-bearing.

The two hardest things — emitting an editable Elementor tree and creating directory accounts at scale — are attempted early. If either is impossible, it is far cheaper to learn in week four than in month four.

M0Foundation — repo, compose stack, RLS pattern, error taxonomy, auth, all seven gates failing loudly on seeded violations
M1Job engine & cost gate — leases, idempotency, side-effect ledger, dead letters, vault, provenance, chaos suite v1
M2Vertical slice — design analysis → DesignIR → one page published as an editable Elementor tree. This milestone decides the product.
M3Content at volume — keyword research, topical map, 50-page fan-out, internal linking, QA calibration
M4Citations — registry, extension, form intelligence, account creation, proof, liveness, cost accounting
M5Web 2.0 & social — 32 platforms, ownership tiering, anchors, pacing, liveness, Parasite Poster
M6Measurement — rank, geo-grid, Search Console, indexing, local & GBP
M7Audit — six paid types plus the free lead magnet, findings contract, narrative constraints
M8Portal, reporting, tiers — tasks, Command Center, capability truth table, client portal, document model, entitlements
M9Hardening & hand-over — chaos across all job kinds, load at 100 clients, restore drill, runbooks, security checklist

If a milestone's exit criteria cannot be met, stop and re-plan. Do not proceed on a known-broken foundation with a note to fix it later — that is precisely how v1 arrived where it did.

13 · Definition of shipped
Eight release gates

Done is demonstrated,
not declared

All eight must be true on production data, with evidence attached. A green test suite is not one of them.

S1 · CONTENT

50 pages, zero repair

Generated, QA'd, reviewed and published to a real site as editable Elementor trees in the client's design system, all passing token conformance.

S2 · CITATIONS

100 live listings

NAP-verified with proof artefacts, and a loaded cost per citation inside the agreed ceiling.

S3 · OFF-PAGE

One campaign, 15+ platforms

Per-client identities, images, internal links, correct SEO fields, official APIs only, no platform ban.

S4 · AUDIT

Six types, no degradation

Each paid audit type completes inside its cost ceiling with zero degraded sections on a fully-keyed environment.

S5 · ISOLATION

Adversarial reads all fail

Cross-tenant access attempted against every table in the schema, and refused by every one.

S6 · TRUTH

No unlabelled number

With every provider key removed, the system displays nothing that is not marked degraded — anywhere in the product.

S7 · RECOVERY

Eight job kinds survive a kill

Each resumes or dead-letters correctly under a mid-run worker kill, and none double-spends.

S8 · RESTORE

Backup restored, verified

Full restore into a clean host, passing a data-integrity check inside the documented recovery objective.

A requirement closed with "tests pass" and no runtime evidence is not closed.
Each closure records what was done, how it was verified in the running system, the evidence reference, and anything deliberately left undone.

v1 → v2

Keep the knowledge.
Replace the architecture.

v1 holds years of SEO domain knowledge worth porting. Its structure is the thing this rebuild exists to replace.

v1v2
Sheets-as-store, then Postgres, then bothPostgres only. Sheets is an export format, never a store

The three lessons, stated plainly

A test that cannot fail is worse than no test

It advertises coverage that does not exist, and it is why 4,900 tests did not catch a filler that failed silently.

Silent degradation is the expensive failure

Every v1 defect that reached a client was the system continuing confidently with data it did not have.

The job contract is the foundation

Not a detail. Work that can run twice, cannot resume, and cannot say what it did will produce every other failure eventually.
